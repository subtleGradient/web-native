React ESM import maps

React, no build step.

These standalone pages demonstrate the 2026 browser-native path: import-map React 19 from an ESM CDN, keep modules native, and transform JSX just in time in the browser when you want the old 2014 ergonomics back.

File-friendly

Inline JSX

One HTML file with an import map, React ESM, Babel standalone, and `data-type="module"`.

 HTTP server

Multi-file JSX

A service worker transforms `.jsx` modules in-browser so native ESM can import them directly.

The recipe

Import maps resolve bare specifiers like react. Babel standalone transforms JSX. The transformed script runs as a native browser module because the script uses data-type="module". 

<script type="importmap">
{
  "imports": {
    "react": "https://esm.sh/react@19.2.0?dev",
    "react/jsx-runtime": "https://esm.sh/react@19.2.0/jsx-runtime?dev",
    "react-dom/client": "https://esm.sh/react-dom@19.2.0/client?dev"
  }
}
</script>
<script src="https://cdn.jsdelivr.net/npm/@babel/standalone@7.28.5/babel.min.js"></script>
<script type="text/babel" data-type="module" data-presets="react-automatic">
  import { createRoot } from "react-dom/client"
  createRoot(root).render(<h1>Hello</h1>)
</script>

2026 notes

  • Import maps are native in modern Chromium, Firefox, and Safari.
  • React 19 no-build demos should use ESM CDN URLs rather than old UMD globals.
  • JSX is still syntax, not a browser feature, so the runtime transformer is the explicit tradeoff.

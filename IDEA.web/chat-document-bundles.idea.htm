Generic Chat Document Bundles

A .chat folder should behave like a portable document: double-clickable on macOS when registered, executable everywhere through a local run file, forkable by folder duplication, and self-contained with all turns, requests, responses, and generated assets inside the bundle.

Principles

  • Avoid OpenAI-specific user-facing names. Use generic chat, AI, provider, model, and transport names.
  • Use TOML for human-authored metadata and turn files.
  • Use JSON5 for raw provider-shaped request and response sidecars.
  • Avoid JSON and JSONL for primary document state.
  • Keep generated assets in the bundle so copying the folder copies the whole conversation.
  • Make filesystem duplication the default conversation fork operation.

Bundle Layout

project.chat/
  run
  Chat.toml
  Settings.toml
  turns/
    000001.user.toml
    000002.assistant.toml
    000003.tool.toml
  requests/
    000001.request.json5
    000001.response.json5
  assets/
    images/
    attachments/
  cache/
    traffic.sqlite

Chat.toml

type = "web-native.chat"
version = 1
title = "Project Idea"
created_at = "2026-05-14T19:00:00Z"
updated_at = "2026-05-14T19:30:00Z"

Settings.toml

[model]
provider = "openai"
name = "gpt-5.5"

[auth]
mode = "api-key-direct"

[storage]
traffic = "cache/traffic.sqlite"
assets = "assets"

Turn File

id = 1
role = "user"
created_at = "2026-05-14T19:31:00Z"
content_type = "text/markdown"

body = """
Continue the conversation from here.
"""

Generated Image Turn

id = 7
role = "assistant"
kind = "image"
created_at = "2026-05-14T19:40:00Z"

[[assets]]
type = "image"
path = "assets/images/000007-001.png"
request = "requests/000007.request.json5"
response = "requests/000007.response.json5"

Portable Run File

The bundle-local run executable is the portable launch surface for macOS and Linux. 

#!/usr/bin/env bash
exec bunx --bun -p https://github.com/subtleGradient/web-native/archive/refs/heads/openai.tar.gz web-native-chat "$(dirname "$0")"

Runner Responsibilities

  • web-native-chat ./project.chat creates missing bundle structure.
  • Serve the chat document UI from the package.
  • Read and write TOML/JSON5 with Bun native support on the server side.
  • Scope provider auth and broker routes to the active bundle.
  • Append turns as TOML files under turns/.
  • Save raw provider request and response sidecars as JSON5 under requests/.
  • Save generated images and attachments under assets/.
  • Write searchable/debuggable traffic into cache/traffic.sqlite.

macOS Document Behavior

Finder can treat specially registered extensions as document packages, but arbitrary folders named *.chat will not automatically open as documents until LaunchServices knows the type. The portable layer is project.chat/run. A later web-native-chat install-macos command can register a tiny app handler for .chat package folders.
